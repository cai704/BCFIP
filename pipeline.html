数据链路总览

1Upstream
上游刷新接口
洛璃的订阅/API，返回实时节点数据（base64 订阅）
https://loli.sub.us.ci/sub
→
2Workflow
GitHub Actions 抓取
luoli.yml 每6小时抓取上游，parse_sub.py 解析出 IP:端口
.github/workflows/luoli.yml
→
3Data File
加工数据文件
生成 txt 格式：IP:端口#备注信息
luoli/all.txt
→
4Deploy
提交 → Pages 部署
有变化才提交，Cloudflare Pages 自动重新部署
bcfip.19870222.xyz
→
5Subscribe
对外订阅
客户端直接订阅的 txt 链接
/luoli/all.txt
以 洛璃 为例：loli.sub.us.ci/sub 是上游源头（实时订阅，仅供工作流抓取）；/luoli/all.txt 是本站成品（每6小时快照，用户客户端订阅的地址）。两者是「实时源 ↔ 定时缓存」的关系。若上游失效，all.txt 仍保留最近一次数据直到源恢复。
